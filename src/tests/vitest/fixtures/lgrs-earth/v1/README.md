# Earth grid reference corpus v1

Reference data for the [Earth grid implementation](../../../../../utils/lgrs/README.md):
WGS84 UTM/UPS, canonical MGRS and the AEGIS ACC Earth labels. Generated by
`scripts/lgrs-reference/src/lgrs_reference/earth.py` with `npm run lgrs:reference-corpus-earth`.
The output is seeded and byte-identical between runs. Don't edit these files by hand.

| Source                                 | Used for                                                       |
| -------------------------------------- | -------------------------------------------------------------- |
| pyproj (EPSG:326xx/327xx, 32661/32761) | E/N, inverse lat/lon                                           |
| PyPI `mgrs` (GeoTrans 3.10, Rust port) | 100 km square IDs (see below), cross-checks                    |
| Independent Python implementation      | zone/band classification, ACC strings, MGRS formatting, digits |

`metadata.json` pins the Python, pyproj, PROJ and `mgrs` versions and the seed. It also records
how the square IDs were sourced, the `mgrs` package cross-check, and the case counts for each
category. The generator stops if the pinned versions aren't installed, if a documented worked
example doesn't reproduce, or if its own square-ID tables ever disagree with `mgrs`.

## Conventions

- **Units:** latitude/longitude in degrees, E/N and distances in metres. Floats are written
  with Python `repr`, so they round-trip exactly through `JSON.parse`. A few classification
  inputs are `-0.0` on purpose.
- **CRS ids:** `0` = UPS S, `1` = UPS N, `2 + (zone - 1) * 2 + (S ? 1 : 0)` = UTM. `system` is
  `"UTM"` or `"UPS"`, `zone` is `1..60` or `null`, and `hemisphere` is `"N"` or `"S"`.
- **Precisions** are metres, used as JSON object keys (strings). ACC: `25000, 1000, 100, 10, 1`.
  MGRS: `100000, 10000, 1000, 100, 10, 1`. Box labels: `100000, 25000, 10000, 1000, 100, 10`.
- **Classification** is exact on the input doubles. N iff `lat >= 0`, and UTM iff
  `-80 <= lat < 84`. Zones own `[west, east)` after conforming longitude to `[-180, 180)`, and
  bands own `[south, north)`, with X = `[72, 84)`. The Norway (31V/32V) and Svalbard
  (31X/33X/35X/37X) exceptions apply.
- **Digits** are `floor` of the oracle E/N: the exact floor of the double, not of a rounded
  quotient. A value exactly on a line belongs to the box east or north of it. The
  `*-ulp-below` cases hold the double just below a line, where `Math.floor(v / p)` can round up
  to the line. Compute `k = Math.floor(v / p)`, then correct it with `k * p > v` (exact for
  these magnitudes).
- **Band:** UTM uses the latitude band letter, and UPS uses `A`/`B` (south) or `Y`/`Z` (north),
  split at E = 2,000,000 (`E < 2,000,000` is `A`/`Y`). The UPS band comes from the easting, so
  it is covered by `boundaryDistance`.

### Label object (`Labels`)

Used by `format-points.json` and `end-to-end.json`:

| Field       | Type                                         | Example (JSC)                                                 |
| ----------- | -------------------------------------------- | ------------------------------------------------------------- |
| `band`      | string                                       | `"R"`                                                         |
| `square`    | string, 2-letter 100 km square ID            | `"TN"`                                                        |
| `accPrefix` | string, `<zone><band><square><E sub><N sub>` | `"15RTNDC"` (UPS: `"ZAPAC"`, no zone)                         |
| `acc`       | `{ [acc precision]: { condensed, full } }`   | `"10": { "condensed": "X51 W77", "full": "15RTNDC X51 W77" }` |
| `mgrs`      | `{ [mgrs precision]: string }`               | `"10": "15R TN 9751 7177"`, `"100000": "15R TN"`              |

- ACC `condensed` is `<E 1 km letter><digits> <N 1 km letter><digits>`, where the 1 km letter
  is `"-ABCDEFGHJKLMNPQRSTUVWXYZ"[floor((v mod 25000) / 1000)]`. There are 3, 2, 1 and 0
  digits at 1, 10, 100 and 1000 m (`"X W"` at 1000 m). `full` is `accPrefix + " " +
condensed`. At 25000 both `condensed` and `full` are the prefix alone, as in lunar display.
- The sub-area letters are `"ABCD"[floor((v mod 100000) / 25000)]`, easting first.
- MGRS is `<zone><band> <square> <E> <N>`, with no zero-padded zone (`1N AA 6603 0001`) and
  `5 - log10(p)` digits per axis. UPS MGRS is `<band> <square> <E> <N>` (`Z AH 0000 0000`).

## Files

### `classification.json` — (a) lat/lon → CRS

`{ "cases": ClassificationCase[] }`

| Field                         | Type                                              |
| ----------------------------- | ------------------------------------------------- |
| `category`                    | string                                            |
| `latitude`, `longitude`       | number (input, unconformed)                       |
| `expected`                    | `null` (invalid latitude) or the object below     |
| `expected.crsId`              | number                                            |
| `expected.system`             | `"UTM"` \| `"UPS"`                                |
| `expected.zone`               | number \| `null`                                  |
| `expected.hemisphere`         | `"N"` \| `"S"`                                    |
| `expected.band`               | UTM band letter, or `null` for UPS (band needs E) |
| `expected.conformedLongitude` | number in `[-180, 180)`, unchanged when in range  |

Categories cover every zone meridian, band parallel, the equator, both UTM/UPS seams, both
poles, the antimeridian, every Norway/Svalbard edge and corner, and interior non-boundaries
(6° E in band V, 80° N and the missing 32X/34X/36X meridians). Each comes exact and at ±1 mm
(`*-exact`, `*-below-1mm`, `*-above-1mm`). The `ulp-*` cases are the adjacent doubles, and
there are also longitude conformation cases, invalid latitudes, `-0.0`, and 1,000 seeded
points. The longitude conformation inputs conform exactly in binary floating point.

### `projection.json` — (b) projection

`{ "cases": ProjectionCase[] }`

| Field                                         | Type                                                |
| --------------------------------------------- | --------------------------------------------------- |
| `category`                                    | string                                              |
| `latitude`, `longitude`                       | number                                              |
| `crsId`                                       | number, the CRS to project into                     |
| `inRegion`                                    | boolean: `crsId` is the point's own classified CRS  |
| `expected.easting`, `expected.northing`       | number, pyproj forward, full precision              |
| `expected.inverseLatitude`/`inverseLongitude` | number, pyproj inverse of those E/N (lon conformed) |

The `neighbour-crs` cases project into the CRS across a nearby zone edge, the equator, or the
UTM/UPS seam, as clipping needs. Projection tolerance: `|ΔE|, |ΔN| ≤ 1 µm`, and round trip
≤ 1 µm.

### `format-points.json` — (c) formatting from CRS + E/N, no projection

`{ "cases": PointFormatCase[] }`

| Field                 | Type                                                                    |
| --------------------- | ----------------------------------------------------------------------- |
| `category`            | string, `utm-*` or `ups-*`                                              |
| `linePrecision`       | number, optional: the grid spacing of the line the case sits on or near |
| `crsId`               | number                                                                  |
| `easting`, `northing` | number (input)                                                          |
| `latitude`            | number, pyproj inverse latitude of the E/N: the UTM band input          |
| `inRegion`            | boolean: the E/N unprojects into this CRS's own region                  |
| `expected`            | `Labels`, formatted in `crsId` whether or not `inRegion`                |

These must match exactly, including values exactly on box lines. Categories are lines exactly
on, ±1 mm from, and one ulp below multiples of each precision (`*-e-line-*`, `*-n-line-*`,
`*-corner-exact`). Others are the equator (N = 0, N = 10,000,000), the 2,000 km row-letter
cycle, and the UPS false easting/northing. Sweeps cover every UTM column and row letter for
zones 13–18 (all three column sets × both row offsets, N and S), and `ups-square-sweep` covers
every UPS 100 km square touching either cap. Squares outside the UTM column range (E < 100 km
or ≥ 900 km) have no label and are left out.

### `format-boxes.json` — (c) box labels

`{ "cases": BoxCase[] }`

| Field            | Type                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| `category`       | string                                                                       |
| `crsId`          | number, the region being drawn                                               |
| `precision`      | number, box size                                                             |
| `lowerLeft`      | `[E, N]`, exact multiples of `precision`                                     |
| `centreLatitude` | number, latitude of `lowerLeft + precision / 2` unprojected in `crsId`       |
| `centreInRegion` | boolean: the box centre classifies into `crsId`                              |
| `expected.band`  | UTM: band of `centreLatitude`, clamped to `[-80, 84)`. UPS: from the easting |
| `expected.acc`   | `{ condensed, full }` at `precision`, or `null` if it isn't an ACC precision |
| `expected.mgrs`  | string at `precision`, or `null` if it isn't an MGRS precision               |

Boxes are labelled in the region's CRS even when their centre lies outside it: partial boxes at
zone edges (`utm-zone-edge-*`, including the Norway and Svalbard zones), boxes split by a band
parallel, and boxes past the 84° N / 80° S seams, whose band is clamped to X or C. There are
also UPS boxes in all four bands, at the false easting split and at the cap edge.

### `end-to-end.json` — (d) lat/lon → strings

`{ "cases": EndToEndCase[] }`

| Field                                            | Type                                               |
| ------------------------------------------------ | -------------------------------------------------- |
| `category`                                       | string                                             |
| `linePrecision`                                  | number, optional (`box-line-*` cases)              |
| `latitude`, `longitude`                          | number (input)                                     |
| `expected.crsId`, `system`, `zone`, `hemisphere` | classification                                     |
| `expected.easting`, `northing`                   | number, pyproj E/N in that CRS                     |
| `expected.boundaryDistance`                      | `{ [precision]: metres }` for all seven precisions |
| `expected.band` … `mgrs`                         | the `Labels` fields                                |

`boundaryDistance[p]` is the minimum over E and N of the distance from the oracle value to the
nearest multiple of `p`. Strings at precision `p` must match exactly when
`boundaryDistance[p] >= 1e-5`. Closer cases (lines, poles, the UPS split, and central meridians,
where pyproj gives E a few ulps below 500,000) must equal one of the two adjacent labels.

The first four cases are the implementation README's worked examples (the fixture category
remains `plan-example`). The generator checks them: JSC `15R TN 9751 7177` / `15RTNDC X51 W77`,
Big Bend `13R FN 7005 3695` /
`13RFNCB V05 L95`, Iceland `28W DS 0499 8766` / `28WDSAD D99 M66`, and antimeridian
`1N AA 6603 0001` / `1NAACA R03 -01`. All four reproduce the documented references and E/N
to the centimetre.
After them come 2,000 seeded global points (area-weighted), 400 polar points (|lat| > 70°), and
20 points within 30 km of each analog site (`site-*`: the USGS sites plus Svalbard and Bergen).
Then come every lat/lon boundary category from `classification.json`, and the `box-line-*`
cases, which sit 1 mm either side of 25 km and 100 km lines. Those are built in projected
coordinates and unprojected with pyproj.

## The `mgrs` package and the reference policy

The implementation README defines the region-selection policy; pyproj supplies E/N. The
`mgrs` package is used for the 100 km square ID only. `metadata.json` → `mgrsPackageCrossCheck` compares
`mgrs.toMGRS(lat, lon, 5)` with every end-to-end case:

- **Exceptions and UPS:** `mgrs` implements the Norway and Svalbard exceptions and the UPS
  polar letter tables. Its zone, band and square agree with the corpus at every exception edge
  and corner.
- **UTM/UPS seams:** GeoTrans keeps UTM for `-80.0000100 <= lat <= 84.0000100` (an epsilon of
  1.75e-7 rad, about 1.1 m). So `lat = 84` exactly is UTM in `mgrs` (`(84, 179)` → `60X …`)
  but UPS here (`Z AP …`), and `-80 - 1 mm` is UTM there but UPS here. The corpus follows the
  documented region-selection policy.
- **Digits:** `mgrs` truncates. Its 1 m digits and squares differ only where the oracle E/N
  is within about 1 mm of a line (max 1.0 mm recorded), because GeoTrans's own projection and
  rounding move such values across it. Digits always come from pyproj.
- **UPS split:** at longitude -180 in the south cap, pyproj's easting is a rounding error below
  2,000,000 (band `A`), where `mgrs` gives `B`. This is a zero-distance boundary case.

Square IDs come from `mgrs` only when it answers for the requested CRS. The package is queried
at the point, clamped 1 cm inside its 100 km square, and the answer is rejected when GeoTrans
files the point under a different zone or band. The generator's own copy of the GeoTrans
letter tables is used instead: AA scheme, column sets by `(zone - 1) % 3`, rows offset by 5 in
even zones, and the polar tables for A/B/Y/Z. That covers points past a region edge (box labels
at zone edges, out-of-region format cases) and UPS points at 84° N exactly. The two sources
agree everywhere both answer (`squareIdSource` in `metadata.json`).
